# 05 · AI evaluation platform

Automated tests for the other projects, using the real project code, scored per model and shown side by side.

**Stack:** [promptfoo](https://promptfoo.dev) · custom Python providers · Ollama `gemma3:12b` as the local judge for `llm-rubric`

## What it tests

| Suite | Tests | Checks |
|---|---|---|
| `rag.yaml` | 10 questions × 2 models (`gemma3:12b`, `qwen3:8b`) | exact facts, "Not in the documents" for questions it can't answer, conflicting sources, a question in Swedish, and every answer cites a source |
| `invoices.yaml` | 5 invoices | exact totals, VAT rates, dates, line counts, and that the wrong invoice is flagged |

The test data is made up: `fixtures/handbook/` is an employee handbook for a fictional studio, plus an old IT FAQ that contradicts it on purpose. Invoices are generated by `03-invoices/make_samples.py`.

`providers.py` runs the actual project code (retrieval + answer, or extraction + checks), not just a bare model, so a change to chunking or prompts shows up in the scores. The RAG suite uses its own database (`.eval-db`).

## Run

```powershell
npm install -g promptfoo
cd 05-eval
promptfoo eval -c rag.yaml -j 1
promptfoo eval -c invoices.yaml -j 1
promptfoo view
```

`-j 1` runs one test at a time; with 12 GB of VRAM, parallel tests make Ollama swap models.

## Golden jobs (coding team)

`golden-jobs\` holds small client-style coding tasks with hidden checks, used to pick and measure the coding
team's models (see `docs\coding-team-blueprint.md`). Each job has `task.md` (all the model is told), `start\`
(the client's code), `hidden\` (tests copied in only while checking) and `job.json` (the check command).
Every job fails as given and passes with a reference solution.

| Job | Stack | Check |
|---|---|---|
| `web-01-todo-api` | ASP.NET Core 8 minimal API + xUnit | `dotnet test`: GET/DELETE by id with 404s, 400 on empty titles, trimmed titles |
| `web-02-shop-cart` | Plain JavaScript modules | `node --test`: rounding bug + discount codes with edge cases |

```powershell
.\.venv\Scripts\python.exe 05-eval\golden-jobs\bakeoff.py --models qwen2.5-coder:7b qwen2.5-coder:14b
```

The model works through the Code tab's own pipeline, on this PC only. A failed check gives the model the
check's output and one more try (`--tries`); `--repeat` runs each job several times. Results and every reply go
to `golden-jobs\.runs\<time>\`.

First bake-off (2026-11-25, 2 runs × 2 tries): `qwen3-coder:30b` 2/4 (both API runs on the first try),
`qwen2.5-coder:7b` 2/4, `qwen2.5-coder:14b` 1/4; nobody passed the cart job yet. Before the parser fix in
`wb_code.py` the same models had scored 0-1 of 2. Details in `docs\coding-team-blueprint.md`.

`--pipeline builder` runs the coding team's Builder instead (SEARCH/REPLACE edits, then the Runner builds and
tests, up to 3 tries per round; restores of the golden jobs' own packages are allowed by the bake-off). Day 3
(2026-11-25, `qwen3-coder:30b`, 3 runs × 2 rounds): todo API 3/3, each on the first try; cart 0/3 (the same 2 of
16 checks each time).

```powershell
.\.venv\Scripts\python.exe 05-eval\golden-jobs\bakeoff.py --models qwen3-coder:30b --pipeline builder --repeat 3
```

`--pipeline team` runs the whole coding team (Scout, Builder, Checker with FIX rounds) and checks only when the
team says it is done; use `--tries 1` for the end-to-end score. Day 4 (2026-11-25): todo API 3/3, cart 1/3.

## Results

| Run | RAG | Invoices |
|---|---|---|
| First run | 16/20 (80 %) | 5/5 |
| After fixing what it found | 20/20 (100 %) | 5/5 |

What the first run caught in `01-rag`, and the fix:

1. **A question in Swedish got "Not in the documents" from both models.** `nomic-embed-text` is English-only. Fix: non-English questions are also searched as an English translation.
2. **Conflicting sources were listed side by side** (4 000 vs 6 000 SEK) without saying which applies. Fix: each chunk now carries its document's title ("IT FAQ (old, 2024)"), and the prompt says to prefer the newer document.
3. **An incomplete answer** about remote work left out the "three days a week" rule. Fix: the prompt asks for the complete answer, including conditions and limits.
